# Drafting Linear Project - Instructions for Claude

## Objective
When asked to draft a Linear project, you need to understand the entire side project's goals and create a comprehensive Linear project structure that fits into those broader objectives.

## Process

### 1. Understanding the Side Project Context
- **Read the project context**: Get the full `context.md` to understand what the overall project is trying to achieve
- **Identify the project's purpose**: What problem is this side project solving?
- **Understand the tech stack**: What technologies are involved and how do they connect?
- **Review existing work**: What's already been built or planned?

### 2. Analyze How This Linear Project Fits
- **Define the scope**: What specific aspect of the side project does this Linear project address?
- **Identify dependencies**: What other projects or components does this depend on?
- **Determine success criteria**: How will we know this Linear project is complete?
- **Consider timeline**: Where does this fit in the overall project roadmap?

### 3. Create the Linear Project Structure

#### Project Overview
Write a clear project overview that includes:
- **Purpose**: What this Linear project accomplishes
- **Goals**: 2-3 specific, measurable outcomes
- **Success Metrics**: How progress will be measured
- **Timeline**: Estimated duration and key milestones
- **Dependencies**: What needs to be completed first
- **Impact**: How this moves the overall side project forward

#### Create 3-6 Issues
For each issue, include:
- **Clear Title**: Descriptive and action-oriented
- **Description**: 
  - What needs to be done
  - Why it's important
  - Acceptance criteria (2-4 specific requirements)
- **Labels**: Appropriate tags (feature, bug, documentation, etc.)
- **Priority**: Based on dependencies and impact
- **Estimate**: Rough complexity/effort level

#### Issue Structure Guidelines
- **Start with foundation**: Infrastructure, setup, core components first
- **Build incrementally**: Each issue should build on previous work
- **Include validation**: Testing, documentation, or review tasks
- **End with integration**: How this connects to the broader project

### 4. Set Status to "Ready for Test Cases"
Once the project overview and issues are created:
- Update all issue statuses to "Ready for test cases"
- This indicates the issues are well-defined and ready for test case development
- The next step will be adding comprehensive test cases to each issue

## Template Structure

### Linear Project Overview Template
```
# [Project Name] - Linear Project

## Purpose
[What this project accomplishes within the broader side project]

## Goals
1. [Specific measurable goal 1]
2. [Specific measurable goal 2]
3. [Specific measurable goal 3]

## Success Metrics
- [How we measure success]
- [Key performance indicators]

## Timeline
- Estimated Duration: [X weeks/months]
- Key Milestones: [Major checkpoints]

## Dependencies
- [What needs to be completed first]
- [External dependencies]

## Impact
[How this advances the overall side project goals]
```

### Issue Template
```
Title: [Action-oriented description]

Description:
**Objective**: [What needs to be accomplished]

**Why**: [Importance and context within the project]

**Acceptance Criteria**:
- [ ] [Specific requirement 1]
- [ ] [Specific requirement 2]
- [ ] [Specific requirement 3]
- [ ] [Specific requirement 4]

**Technical Notes**: [Implementation considerations]

Labels: [feature/bug/documentation/etc.]
Priority: [High/Medium/Low]
Estimate: [1-5 or t-shirt sizes]
```

## Key Principles
- **Clarity**: Each issue should be clear enough for anyone to understand and execute
- **Completeness**: All necessary work should be captured in issues
- **Connectivity**: Show how this Linear project advances the overall side project
- **Actionability**: Every issue should have clear next steps and success criteria
- **Testability**: Issues should be structured so test cases can be easily added later

## Common Pitfalls to Avoid
- Don't create issues that are too large or vague
- Don't skip foundation/setup work
- Don't forget documentation and testing tasks  
- Don't create issues without clear acceptance criteria
- Don't lose sight of how this fits into the bigger picture

Remember: The goal is to create a well-structured Linear project that meaningfully contributes to the overall side project's success and is ready for detailed test case development.
